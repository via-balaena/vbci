# Data catalogue

Every table and view in the warehouse, as DuckDB describes them, with the comments
`crates/warehouse/schema.sql` and the loader give them. Generated by
`cargo run -p balaena-warehouse -- catalogue`; the test `the_catalogue_is_current` fails
when this file differs from what that would write. Change the schema, not this file.

## bronze

### bronze.record

A table. Every record file the loader read, exactly as read.

| column | type | what it is |
|---|---|---|
| path | VARCHAR | The file's path, relative to the repo root. |

Other columns: `body` VARCHAR.

### bronze.record_hash

A view. Lineage: the sha256 of each record file's text.

Columns: `path` VARCHAR, `sha256` VARCHAR.

## silver

### silver.diet_category

A table. The class of each USDA category, from diet/categories.toml: plant, dairy_and_egg, flesh or mixed.

Columns: `description` VARCHAR, `class` VARCHAR, `record` VARCHAR.

### silver.diet_exception

A table. Each exception for one food, from diet/exceptions.toml, with the reason.

Columns: `fdc_id` INTEGER, `description` VARCHAR, `vegan` VARCHAR, `vegetarian` VARCHAR, `why` VARCHAR, `record` VARCHAR.

### silver.diet_rule

A table. Each naming rule, from diet/rules.toml: within its category, a food whose USDA name starts with starts_with takes the answers the rule gives.

Columns: `category` VARCHAR, `starts_with` VARCHAR, `vegan` VARCHAR, `vegetarian` VARCHAR, `why` VARCHAR, `record` VARCHAR.

### silver.diet_taxon

A table. The group of each organism a Foundation food records, from diet/taxa.toml.

Columns: `taxon` VARCHAR, `name` VARCHAR, `organism` VARCHAR, `record` VARCHAR.

### silver.ingredient

A table. Each of VBCI's own ingredients, from ingredients/<id>.toml.

Columns: `ingredient` VARCHAR, `name` VARCHAR, `wikidata` VARCHAR, `record` VARCHAR.

### silver.ingredient_alias

A table. Each name a recipe may call an ingredient by; an alias names one ingredient.

Columns: `alias` VARCHAR, `ingredient` VARCHAR.

### silver.ingredient_form

A table. Each form of an ingredient: a state linked to one USDA food in the pinned release, with USDA's name for it. Position 1 is the default.

Columns: `ingredient` VARCHAR, `state` VARCHAR, `position` INTEGER, `fdc_id` INTEGER, `description` VARCHAR.

### silver.nutrient

A table. Each nutrient VBCI reports, from nutrients.toml, in the record's order.

Columns: `nutrient` VARCHAR, `position` INTEGER, `name` VARCHAR, `unit` VARCHAR, `record` VARCHAR.

### silver.nutrient_code

A table. Each USDA nutrient_nbr a nutrient is found by, first choice first.

Columns: `nutrient` VARCHAR, `priority` INTEGER, `code` VARCHAR.

### silver.usda_category

A table. Each food category of each dataset, from food_category.csv.

Columns: `dataset` VARCHAR, `id` INTEGER, `description` VARCHAR.

### silver.usda_food

A table. Every SR Legacy and Foundation food, meat included, from food.csv. The Foundation zip's sample and acquisition rows stay in bronze.

| column | type | what it is |
|---|---|---|
| fdc_id | INTEGER | USDA's FoodData Central id, unique across both datasets. |

Other columns: `dataset` VARCHAR, `data_type` VARCHAR, `description` VARCHAR, `category_id` INTEGER.

### silver.usda_food_common_name

A table. Each "Common Name" attribute (type 1000) a food carries, as written: often several names, comma-separated, and sometimes a tag rather than a name.

Columns: `fdc_id` INTEGER, `dataset` VARCHAR, `common_name` VARCHAR.

### silver.usda_food_foodon

A table. Each FoodOn id a food carries, from food_attribute.csv's "FoodOn Ontology ID For FDC Item"; Foundation foods carry them, SR Legacy's bulk files do not.

Columns: `fdc_id` INTEGER, `dataset` VARCHAR, `foodon` VARCHAR.

### silver.usda_food_nutrient

A table. Each amount of a nutrient in 100 g of a silver food, from food_nutrient.csv.

| column | type | what it is |
|---|---|---|
| source_id | VARCHAR | The row's id in food_nutrient.csv, as written. |

Other columns: `fdc_id` INTEGER, `dataset` VARCHAR, `nutrient_id` INTEGER, `amount` DOUBLE.

### silver.usda_food_taxon

A table. The source organism's group each Foundation food records, from food_attribute.csv's "NCBI Taxon Parent", once per food; a food recorded as NA has none.

Columns: `fdc_id` INTEGER, `dataset` VARCHAR, `taxon` VARCHAR.

### silver.usda_nutrient

A table. Each nutrient of each dataset, from nutrient.csv. Keyed by dataset: the same id can name a nutrient differently in two releases.

| column | type | what it is |
|---|---|---|
| nbr | VARCHAR | USDA's nutrient_nbr, as text exactly as written (269.3 is not 269); NULL where USDA gives none. |

Other columns: `dataset` VARCHAR, `id` INTEGER, `name` VARCHAR, `unit` VARCHAR.

### silver.usda_rejected

A table. Each nutrient row of a silver food that silver did not keep, and why: no amount, a nutrient its dataset lacks, a repeat of an earlier row, or a disagreement with another.

| column | type | what it is |
|---|---|---|
| source | VARCHAR | The bronze table the row is in. |
| id | VARCHAR | The row's id in that table, as written. |

Other columns: `dataset` VARCHAR, `reason` VARCHAR.

## gold

### gold.alias_candidate

A view. Names USDA's data gives a linked food that no ingredient lists as an alias yet: unknown until a person reviews one into an ingredient's aliases. From SR Legacy's common names and from the parentheses in USDA's names, less notes such as "Includes foods for ...".

Columns: `ingredient` VARCHAR, `candidate` VARCHAR, `source` VARCHAR, `fdc_id` INTEGER.

### gold.food_diet

A view. Each food's vegan and vegetarian answers, yes, no or unknown, and what decided each: an exception, a naming rule, an animal organism, or the category's class, the first that applies.

| column | type | what it is |
|---|---|---|
| vegan | VARCHAR | By The Vegan Society's definition: no product derived wholly or partly from animals. |
| vegetarian | VARCHAR | By the Vegetarian Society's criteria: no meat or fish, and no slaughter by-product such as animal rennet, gelatine or carcass fat. |

Other columns: `fdc_id` INTEGER, `dataset` VARCHAR, `description` VARCHAR, `category` VARCHAR, `vegan_basis` VARCHAR, `vegetarian_basis` VARCHAR.

### gold.food_nutrient

A view. Each food's amount of each nutrient VBCI reports, per 100 g: from the first of the nutrient's codes the food has a value for.

| column | type | what it is |
|---|---|---|
| code | VARCHAR | The USDA nutrient_nbr the amount came from. |

Other columns: `fdc_id` INTEGER, `dataset` VARCHAR, `nutrient` VARCHAR, `amount` DOUBLE, `unit` VARCHAR.

### gold.ingredient_form

A view. Each form of each ingredient, with its USDA food, whether it is the default, the FoodOn ids that food carries, and how many of the nutrients VBCI reports it has a value for.

| column | type | what it is |
|---|---|---|
| foodon | VARCHAR | Derived, never typed: the FoodOn ids USDA's data gives the linked food. |

Other columns: `ingredient` VARCHAR, `state` VARCHAR, `is_default` BOOLEAN, `fdc_id` INTEGER, `dataset` VARCHAR, `description` VARCHAR, `nutrients` BIGINT.

### gold.nutrient_coverage

A view. For each dataset and nutrient VBCI reports: how many of its silver foods have a value.

Columns: `dataset` VARCHAR, `nutrient` VARCHAR, `position` INTEGER, `unit` VARCHAR, `foods` BIGINT, `with_value` BIGINT.

### gold.nutrient_source

A view. For each dataset and nutrient: how many foods took their value from each code.

Columns: `dataset` VARCHAR, `nutrient` VARCHAR, `code` VARCHAR, `foods` BIGINT.
